Send TARI like a gift card.

Lock TARI behind a secret redemption code, write a message, and share it anywhere — a chat, an email, a birthday card. Anyone with the code can claim the gift. No wallet address needed up front.

Create a gift card ↓
🔒

1 · Lock

Create a card with an amount, a message and an optional expiry. Only the SHA-256 hash of the redemption code is stored — never the code itself.

💌

2 · Share

Send the card ID and code to your recipient however you like. The code is the key: whoever holds it can redeem the full amount.

↩️

3 · No waste

If the gift is never claimed, the creator can reclaim the funds after the expiry — gifts never get stuck forever.

The app

The full gift-card flow, running in your browser.

🎁 Create a gift card

A redemption code is generated for you. Only its SHA-256 hash is kept on the card.

🔑 Redeem a gift card

Received a gift? Enter the card ID and the redemption code to claim it.

My gift cards

Cards created or redeemed in this browser. After a card expires, its creator can reclaim the funds here.

On-chain

OotleGift is a real Tari Ootle template written in Rust (GiftCard), verified by engine tests that run the actual Ootle execution engine. The template enforces exactly the rules this page simulates: SHA-256 code check, one-time redemption, owner-only reclaim after expiry.

  • Template: GiftCard — publication to the Esmeralda testnet is in progress; the template address will appear here.
  • Source code & tests: github.com/5himq/ootlegift (MIT license)
  • Network: Tari Ootle — Esmeralda testnet (indexer: esme-indexer-a.ootle.tari.com)
Honest labelling: this hosted demo is a browser simulation of the template's rules (state is kept in your browser's local storage, and amounts are simulated TARI). The on-chain rules live in the Rust template in the repository, which is covered by engine tests. No real funds move on this page.
